CiM Merge & Fragment

Interactive visualization of how cim merge combines targets and how fragments layer modifications on top.

cim merge — Two Targets, No Fragment

Peer merge: items combined by unique key, conflicts abort. First target wins for scalars. Global targets omitted.

Merge Rules:
• Gits: matched by name. Identical → deduplicated. Different → conflict.
• Toolchains: matched by get_name(). Same logic as gits.
• Variables: combined. Same key + different value → conflict.
• Mirror: first target wins. Note printed if they differ.
• Global targets (build, test, clean, flash, envsetup): omitted — shown as comments.

cim merge — With Fragment Override

Targets merged first, then fragment applied. Fragment resolves conflicts and supplies global targets.

With --fragment:
• Merge runs first — conflicts are recorded but not immediately fatal.
• Fragment keys that match a conflict → conflict removed from the list.
• Fragment can supply build, test, clean, flash, envsetup directly.
• Only conflicts NOT covered by the fragment cause an abort.
• Fragment can also remove_gits, remove_toolchains, etc.

cim fragment — Layer on Existing Config

Fragments are overlays: remove first, then add/modify, then replace scalars. Fragment always wins.

Fragment Apply Order:
1. Remove — remove_gits, remove_toolchains, remove_copy_files, remove_install
2. Add/Modify — List items matched by key: if found → deep-merge (only Some fields override). If new → append.
3. Variables — Shallow merge, fragment values win on collision.
4. Scalars — mirror, build_folder replaced entirely.
5. Global targets — build, test, clean, flash, envsetup replaced entirely.
6. Makefile include — files and exclude lists appended.
